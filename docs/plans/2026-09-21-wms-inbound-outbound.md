## 2. 正向流程

### 2.1 入库

```text
MES 商品发货
  → 生成收货单 SO（待收货）
  → 到货扫描（记到货人时，不单独占状态）
  → 收货扫描（累加实收；可部分）
  → 首次实收 > 0 时生成唯一入库单（待质检）
  → 质检（合格 / 不合格 / 维修；合计 ≤ 实收）
  → 确认入库：生成唯一 SJ，应上架数 = 当前合格数
  → 上架完成：已上架 = 应上架
```

之后若继续收货、补质检：仍是同一张入库单、同一个 SJ；应上架数随合格数增加。若应上架 > 已上架，SJ 从「已上架」回到「部分上架」。

### 2.2 出库

```text
OMS 锁库并下发
  → WMS 待出库单（待出库，未入波）
  → 下发波次（创建即下发，无草稿）
  → 按 SKU 聚合生成配货单 PH（同一 SKU 一张）
  → 配货 / 分拣
  → 关联订单进入待复核
  → 复核通过 → 已复核
```

订单列表只露出四段状态。待出库内部用字段「作业进度」区分：未入波 / 已入波 / 配货中，不另做 Tab。

## 3. 状态机（含逆向）

逆向原则：

- 每一步正向都有对称回退，除非下游已经消耗数量。
- 回退被拦截时，提示必须写明**先回退哪一张下游单据**。
- 作废 / 取消不是删除；终态可在满足条件时恢复。

### 3.1 收货单 SO

| 状态 | 含义 |
| --- | --- |
| `pending` 待收货 | 已生成，实收 = 0 |
| `partial` 部分收货 | 0 < 实收 < 送货 |
| `received` 全部收货 | 实收 ≥ 送货 |
| `void` 作废 | 不再作业 |

正向：`pending → partial → received`（也可一次收齐 `pending → received`）。

逆向：

| 动作 | 规则 |
| --- | --- |
| 反收货 | 减少实收。实收不得低于已质检数量（合格+不合格+维修）。减到 0 → `pending`；仍不足送货 → `partial` |
| 作废 | 仅当上架已完成数 = 0。级联作废入库单与未上架的 SJ。若已有上架数量，拦截并提示先撤回上架 |
| 恢复 | 本期不做「作废恢复」，避免和已释放的单号语义冲突 |

### 3.2 入库单

| 状态 | 含义 |
| --- | --- |
| `qc_pending` 待质检 | 首次收货生成 |
| `qc_doing` 质检中 | 已开始，结果未确认完毕 |
| `qc_done` 质检完成 | 本轮质检数已提交，尚未确认入库 |
| `inbound_done` 已入库 | 已确认并挂上 SJ |
| `void` 作废 | 随收货单作废 |

正向：`qc_pending → qc_doing → qc_done → inbound_done`。

逆向：

| 动作 | 规则 |
| --- | --- |
| 质检回退 | 首次：`qc_doing → qc_pending`（清空草稿）；`qc_done → qc_doing`。补质检（从 `inbound_done` 进入）：回退恢复快照并回到 `inbound_done`，不清空已确认数量。若界面仍显示已入库，须先取消确认入库才能走首次清空路径 |
| 取消确认入库 | `inbound_done → qc_done`，仅当 SJ 已上架数 = 0。SJ 改为作废（单号不复用；再次确认时复用同一 SJ 记录并恢复为待上架，仍保持 1:1） |
| 数量底线 | 质检合计不得低于已上架数，不得高于实收 |

边收边检：收货单仍为部分收货时，允许入库单处于质检中及之后状态。

### 3.3 上架任务 SJ

| 状态 | 含义 |
| --- | --- |
| `pending` 待上架 | 已生成，已上架 = 0 |
| `partial` 部分上架 | 0 < 已上架 < 应上架 |
| `done` 已上架 | 已上架 ≥ 应上架 |
| `void` 作废 | 取消确认入库或收货作废，且已上架 = 0 |

正向：上架累加。逆向：撤回上架，减少已上架数，状态按数量回退 `done → partial → pending`。已上架数不能为负。

### 3.4 待出库单

| 状态（Tab） | 含义 |
| --- | --- |
| `wait_out` 待出库 | 已下发到 WMS，尚未进入复核 |
| `check_pending` 待复核 | 关联配货单已配货完成 |
| `checked` 已复核 | 复核通过 |
| `cancelled` 已取消 | 取消 |

逆向：

| 动作 | 规则 |
| --- | --- |
| 反复核 | `checked → check_pending` |
| 取消 | 仅 `wait_out` 且未入波。已入波必须先取消波次；待复核必须先撤回配货。已复核必须先反复核 |
| 恢复 | `cancelled → wait_out`（未入波） |

### 3.5 波次

无草稿。状态只有：

| 状态 | 含义 |
| --- | --- |
| `released` 已下发 | 创建即此状态，并已生成配货单 |
| `done` 完成 | 波次内仍有效的订单都已进入待复核或已复核 |
| `cancelled` 已取消 | 逆向取消 |

逆向：取消波次仅当旗下配货单全部为「待配货」或「已取消」。否则提示先撤回配货。取消后：配货单 → 已取消，订单回到待出库并清空波次关联。

下发规则：只收「待出库且未入波」的订单；按 SKU 聚合生成配货单（同 SKU 一单）。单件（一单一 SKU 且数量订单只有一笔）配货完成可跳过分拣；多笔订单聚合须经待分拣。

### 3.6 配货单

| 状态 | 含义 |
| --- | --- |
| `to_pick` 待配货 | |
| `to_sort` 待分拣 | 多单聚合拣完 |
| `picked` 已配货 | 关联订单可进入待复核 |
| `shortage` 缺货 | |
| `cancelled` 已取消 | 随波次取消，或待配货时单独取消 |

正向：`to_pick → to_sort → picked`，或单件 `to_pick → picked`。缺货：`to_pick / to_sort → shortage`。

逆向：

| 动作 | 规则 |
| --- | --- |
| 撤回 | `to_sort → to_pick`；`picked → to_sort`（单件则回到 `to_pick`）。若关联订单已是已复核，拦截并提示先反复核。撤回后订单从待复核回到待出库 |
| 缺货恢复 | `shortage → to_pick` |
| 取消 | 仅 `to_pick`。若因此波次内已无待作业配货单，不自动取消波次（避免误伤其他 SKU）；波次取消仍走波次动作 |

## 4. 逆向顺序（操作员视角）

入库从下游往上游拆：

```text
撤回上架 → 取消确认入库 → 质检回退 → 反收货 → 作废收货单
```

出库从下游往上游拆：

```text
反复核 → 撤回配货（缺货则先恢复）→ 取消波次 → 取消待出库单
恢复取消单：已取消 → 待出库
```
