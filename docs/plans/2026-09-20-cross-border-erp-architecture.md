## 1. 产品定位

面向跨境品牌 / 工贸一体或代工协同卖家，将「产品运营 → 打版核价 → 采购生产 → 工厂执行 → 仓储履约 → 订单履约」串成可追溯链路的一体化 ERP。

各模块可独立演进，但共享主数据与事件契约，避免做成六个互不连通的系统。

---

## 2. 模块职责边界

（以下为用户确认版职责表）

| 模块 | 职责重心 | 典型对象 |
|------|----------|----------|
| **PLM** 产品运营 | 产品创建、产品刊登、售前规则、打样需求评估、备货计划 | SPU、SKC、SKU |
| **PDM** 产品打版 | 打样需求、BOM 物料信息、纸样、产品核价 | 打样单、BOM、纸样、核价单 |
| **PTM** 生产计划 | 采购单、生产进度管理 | 采购单（PO）、生产进度 |
| **MES** 工厂执行 | 采购单执行 | 工厂工单 / 采购单执行进度 |
| **WMS** 仓储 | 采购单入库、库内管理、出库管理、盘点、移库 | 仓库、库位、库存事务、出入库单 |
| **OMS** 订单 | Shopify 收单、审单、拆合单、履约指令、售后 | 订单、履约单、退货 |

### 边界说明（相对初版的关键校正）

- **商品层级定为 SPU → SKC → SKU**（PLM 权威；WMS 库存落在 SKU）。
- **PDM** 聚焦打版 / BOM / 纸样 / 核价，不再泛化为「全部工程研发」。
- **PTM** 以 **采购单（PO）+ 生产进度** 为核心，独立保留。
- **MES** 承接采购单在工厂侧的执行。
- **WMS** 入库主路径对齐 **采购单入库**；出库对齐 OMS 履约指令。
- **OMS** 首期渠道明确含 **Shopify**（后续可扩展其他渠道）。

### 待需求中再明确（不影响架构）

- **首发客户形态**（纯贸易 / 工贸一体 / 多货主）：影响 WMS 首期是否含原料仓、多货主等；在 WMS 需求中确认。

## 3. 业务主链路

```text
PLM（创建 SPU/SKC/SKU，刊登与备货计划）
  → PDM（打样、BOM、纸样、核价）
    → PTM（下采购单，跟踪生产进度）
      → MES（工厂执行采购单）
        → WMS（采购单入库 → 库内管理）
          ← OMS（Shopify 订单 → 履约指令 → WMS 出库）
```

### 跨境横切能力

1. **多仓多主体**：国内仓 / 海外仓 / 中转仓；多法人、多货主（按阶段引入）
2. **多渠道履约**：Shopify（及后续渠道）→ OMS → WMS 出库
3. **全链路追溯**：批次/序列号：采购/生产 → 入库 → 出库 → 售后

## 4. 系统分层架构

```text
┌─────────────────────────────────────────┐
│  应用层：OMS / PLM / PDM / PTM / MES / WMS │
├─────────────────────────────────────────┤
│  领域服务：库存账、单据引擎、工作流、规则引擎 │
├─────────────────────────────────────────┤
│  主数据 MDM：SPU/SKC/SKU、仓库、库位、供应商 │
├─────────────────────────────────────────┤
│  集成层：Shopify、物流、工厂、事件总线       │
├─────────────────────────────────────────┤
│  基础能力：组织权限、多租户、审计、国际化/多币种 │
└─────────────────────────────────────────┘
```

### 与 WMS 先行强相关的底座子集

- 组织与权限（租户、仓库、角色）
- **商品主数据最小集**（SPU/SKC/SKU，非完整 PLM）
- 库存账本模型（可用 / 占用 / 在途；正品 / 次品等）
- 单据与状态机（采购入库 / 出库 / 调拨 / 盘点 / 移库）
- 事件出口（库存变更、出库完成等，供 OMS/PTM/MES 后续订阅）

## 5. 主数据策略（关键决策）

### 5.1 区分「商品主数据」与「完整 PLM」

| 概念 | 内容 | 本期策略 |
|------|------|----------|
| **商品主数据（MDM 最小集）** | SPU/SKC/SKU、条码、包装规格、批次/效期属性、单位换算 | **与 WMS 同步建立，可手工维护** |
| **完整 PLM** | 产品创建全流程、刊登、售前规则、打样需求评估、备货计划 | **后置建设；建成后成为商品资料权威源** |

### 5.2 PLM 上线后的对接方式

- **可以对接，不是推倒重来。**
- 前提：WMS 从第一天使用稳定的 SKU 身份（全局唯一 ID/编码），商品表可被外部同步。
- 对接后分工：
  - SPU/SKC/SKU、条码、单位、箱规、批次/效期标志 → 由 MDM/PLM 维护，WMS 消费
  - 库位、库存数量、出入库流水 → **WMS 权威**
  - 刊登、售前规则、备货计划 → **PLM 权威**
- 同步形态：PLM 创建/变更商品 → 接口或事件推送 WMS → 建档或更新资料

### 5.3 商品主数据最小字段（WMS 期预埋）

- **SPU / SKC / SKU** 编码、名称、状态（启用/停用）
- 条码、基本单位、箱规（件/箱）
- 是否批次、是否效期、是否序列号
- 体积 / 重量（出库与运费预留）
- 同步预留：`external_id` / `source` / 同步时间（便于 PLM 接管）
- （可选）货主 / 品牌 —— 若存在多货主再启用

> 库存事务一律挂在 **SKU**；SKC/SPU 用于汇总与运营视角。

## 6. 模块间关键契约（预留）

1. **PTM → WMS**：采购单入库预期（SKU、数量、预计到货、供应商等）
2. **MES → WMS / PTM**：采购单执行进度、完工可入库信号
3. **OMS → WMS**：履约出库指令（SKU、数量、仓库、收件信息）
4. **WMS → OMS**：出库结果 / 运单 / 短缺
5. **WMS → 全系统**：库存变更事件（可用量变化为公共事实）
6. **PLM → WMS / OMS / PDM**：SPU/SKC/SKU 主数据下发

首期 WMS 实现库存账与单据即可；对外契约以接口/事件形状预留，不强绑未建模块。  
WMS 首期可用「手工创建入库单」模拟采购单入库，待 PTM 就绪后改为按 PO 收货。

## 7. 搭建执行策略（已批准）

### 原则

- **壳要薄、纵切要深**
- 不先做完整 PLM，再灌数据给下游
- 不把六大模块业务页全部做完再补数据
- 因对 WMS 更熟悉，以 WMS 作为首个可验证业务闭环

### 阶段划分

#### 阶段 0 — 全产品薄壳 + 最小底座

- 统一布局、导航、各模块入口占位（每模块 1～2 个空状态/入口页即可）
- 组织权限、仓库维度
- 商品主数据最小集（可手工建 SPU/SKC/SKU）
- 库存账本 + 单据框架

**成功标准：** 导航完整、权限可用、商品可建、账本模型定稿。

#### 阶段 1 — WMS 纵切（当前重点）

与职责表对齐的能力包（细节以用户后续 WMS 需求为准）：

1. 仓库 / 库区 / 库位（库内管理基础）
2. **采购单入库**（首期可手工入库单，预留 PO 关联字段）
3. **出库管理**（对齐后续 OMS 履约指令）
4. 库存查询与占用
5. **盘点**
6. **移库**
7. 批次或效期（跨境常需，可先简后繁）

**刻意延后：** 复杂波次、自动分仓、全自动播种等高级算法。

**成功标准：** 入库 → 上架/库内 → 出库 → 库存账一致，可演示。

#### 阶段 2 — OMS

Shopify 收单、审单、拆合单、履约单下发 WMS、发货回传、基础售后。  
**成功标准：** Shopify 订单 → 占用库存 → 出库 → 物流回传。

#### 阶段 3 — 完整 PLM

产品创建、刊登、售前规则、打样需求评估、备货计划；接管 SPU/SKC/SKU 同步至下游。

#### 阶段 4 — PDM → PTM → MES

打版/BOM/核价 → 采购单与进度 → 工厂执行；与 WMS 打通 **采购单入库**。

#### 阶段 5 — 跨境增强

海外仓、头程、多主体、全链路追溯、多渠道扩展等。

## 8. 明确不采用的做法

| 做法 | 结论 |
|------|------|
| 先做完整 PLM，再做下游 | 不采用（完整 PLM 后置） |
| 各模块业务页全部搭完再灌数据 | 不采用（仅允许薄壳占位） |
| WMS 私有一套临时商品码、后期硬拧 | 不采用（稳定 SKU 身份 + 可同步） |
